# AI Workbench Bridge

Open a workspace containing `.harness/bridge.json`. The extension connects to the local Workbench server, opens a new Copilot Agent chat and inserts the queued prompt. Automatic submission is on by default. Toggle **Automatic chat** in the dashboard to prepare future prompts for manual Send. The **AI Workbench: Auto Submit** user setting can also disable automatic submission globally.

For Docker workspaces, use **Open VS Code** in the dashboard to attach to the existing Linux container. The bridge is a UI extension running on the Windows host. It reads the remote bridge configuration through VS Code's filesystem API, verifies its host-side copy, and exchanges response/progress files through the shared workspace folder. The server stays on host loopback; no host-network listener is needed. Copilot terminal tools and demos run in the Linux container. Opening only the Windows folder does not dispatch jobs for container workspaces.

The coding agent writes a structured reply to `.harness/responses/<jobId>.json`. The extension forwards it to the dashboard. This remains the main flow for questions and completion. As a last resort, generated Local agent hooks recover native question-tool calls or explicit final chat question lines into that same JSON file and stop the request. The normal bridge completes the job and the dashboard collects answers for a new request. Existing replies take precedence. Recovery requires Local hooks enabled in a current VS Code version; chat-only recovery depends on Copilot's current hook transcript format. There is no Copilot CLI, chat database access, or UI scraping. Activity history runs automatically on the server every 30 seconds during work, using AI-reported progress and completion messages with at most 50 words per entry. No enable command is needed. Optionally run **AI Workbench: Enable Activity Summaries** to choose a separate Copilot model to rewrite summaries through the VS Code Language Model API; model consent and availability apply to this optional enhancement. No private reasoning is collected.

The server enables automatic tool approval for newly generated workspaces by default. Before each new chat, the bridge sets workspace `chat.permissions.default` to `autoApprove` or `default` according to the server's persisted workspace choice. Set `AIWORK_AUTO_APPROVE=false` when starting the server to create workspaces with manual tool approval. Automatic submission is a separate control; human questions, requirements and result approval still use the dashboard. VS Code workspace trust, Copilot sign-in, model access and organization policies remain in effect. The chat-opening commands are VS Code workbench commands rather than a stable public extension API and may change between versions. Connection errors appear in Output → AI Workbench and the dashboard. Use **AI Workbench: Send Pending Prompt** to explicitly submit a prepared request.
